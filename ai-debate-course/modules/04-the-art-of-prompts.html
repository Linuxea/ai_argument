The Art of Prompts

How each debater gets a unique personality — and why it changes every turn

Two Kinds of Prompts

Imagine a theater director giving each actor personalized notes before every scene — not just at the start of the play. Before each debater speaks, the app sends two separate messages to the LLM. Each serves a different purpose.

🎭
System Prompt (the personality)

"Who you are, what you believe, how you should behave." This tells the AI its role — supporter, critic, or analyst. It includes the rules of debate, the current round number, and the debater's unique personality. It is rebuilt from scratch before every single turn.

💬
User Prompt (the situation)

"Here is what is happening right now." This delivers the debate topic and what everyone else has said so far. It changes every turn as the debate evolves. Think of it as the director saying "here is where the story has reached — now say your line."

The system prompt defines identity. The user prompt delivers context. Together, they give the AI everything it needs to play its part.

The 5-Part Recipe

The system prompt is not one big block of text. It is assembled from separate ingredients, like a recipe. A function called _build_debater_instructions combines these parts every time a debater takes a turn.

1
Date context

"Today is 2026-04-03. The current year is 2026." This goes first so the AI knows what "recent" and "current" actually mean. Without it, the AI might cite outdated information.

2
Debate rules

The shared rules every debater follows: be concise, respond to others, use [[Name]] for mentions, no bare assertions, no personal attacks. These are the same for everyone.

3
Stance

"You support the topic" (正方) or "You oppose the topic" (反方) or "You take a balanced view" (中立). This is the debater's team assignment — which side they argue for.

4
Personality

The unique persona from presets.yaml: "你是正方——你的职责是为辩题提供有力支撑..." This is what makes each debater sound different from the others.

5
Search instructions (if enabled)

Round 1: search actively for facts. Round 2+: conserve, max 1 search per round. Only debaters with search capability get this part. The analyst, for example, skips it entirely.

6
Round countdown

"This is round 3 of 10. There are 6 rounds remaining." Or on the last turn: "FINAL ROUND. Make your strongest closing argument." This is why the prompt must be rebuilt every turn — the countdown changes.

These parts are joined with a separator line (\n\n---\n\n) to create one complete instruction block. The result is a fresh, context-aware system prompt for every single turn.

The Builder Function

Here is the actual code that assembles the system prompt. On the left is the Python function. On the right is what each line does in plain English.

Python · agents.py def _build_debater_instructions(ctx: RunContext[DebaterDeps]) -> str: debater = ctx.deps.debater stance = STANCE_INSTRUCTIONS.get(debater.stance, ...) now = datetime.now() date_context = ( f"**CURRENT DATE: {now.strftime('%Y-%m-%d')}**\n" f"The current year is **{now.year}**." ) parts = [ date_context, DEBATE_RULES, f"Your stance: {stance}", debater.personality, ] if debater.enable_search: parts.append(SEARCH_INSTRUCTIONS) if ctx.deps.max_rounds: remaining = max_r - ctx.deps.round_number if remaining <= 1: parts.append("FINAL ROUND...") else: parts.append(f"round {current} of {max_r}...") return "\n\n---\n\n".join(parts)
What this means
This function builds the system prompt from scratch every time a debater takes a turn. The RunContext carries all the info it needs.
Look up what stance this debater has: supporter (正方), opponent (反方), or neutral (中立).
Get the current date so the AI knows what "recent" means when it talks about events.
Start assembling the parts: today's date, the shared debate rules, the debater's stance, and their unique personality.
If this debater has search enabled, add the search strategy instructions too.
If there are limited rounds, add a round countdown — or "FINAL ROUND" if it's the last one.
Join all parts with a separator line. The result is one complete system prompt — a string of text ready to send to the AI.

Notice how the function uses dependency injection — the ctx object carries everything in. The function never reaches out to find the debater's name or the round number. It simply unpacks what was handed to it.

The User Prompt — What Goes In

While the system prompt defines who the AI is, the user prompt tells it what is happening. A separate function called _build_user_prompt constructs this every turn. Here is how it works.

Python · debate_engine.py def _build_user_prompt(self, debater: Debater) -> str: if not self.state.history: return ( f"You are the first speaker. " f"No one has spoken yet - do NOT reference " f"or quote anyone. Present your opening " f"argument on the topic: {self.state.topic}" ) parts = [f"Debate topic: {self.state.topic}"] for msg in self.state.history: if msg.speaker == debater.name: continue parts.append(f"[{msg.speaker}]: {msg.content}") return "\n\n".join(parts)
What this means
If this is the very first turn and no one has spoken yet, give a special opening prompt with just the topic.
Otherwise, start by restating the debate topic so the AI always knows what it's arguing about.
Go through every message in the debate history so far, one by one.
Skip this debater's own past messages — those are already in the AI's memory through PydanticAI's built-in message history.
Include everyone else's messages so the debater can respond to them.
Join everything into one string and send it as the user prompt.

The clever part is the skip. A debater's own past messages are already stored in PydanticAI's internal message history (self._history). So the user prompt only needs to include what other people said. This avoids repeating the debater's own words back to it.

💡
Key Insight

The split between system prompt and user prompt is the most important concept in AI app design. The system prompt defines WHO the AI is. The user prompt defines WHAT'S HAPPENING right now. When you are building AI apps, the system prompt is your "configuration" and the user prompt is your "data." This separation lets you change the AI's behavior (system prompt) without changing the situation (user prompt), and vice versa. This is the foundation of all prompt engineering.
