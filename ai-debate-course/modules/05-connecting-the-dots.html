Patterns Worth Knowing

Every codebase has a few clever tricks tucked inside. Here are three worth remembering — not because you need to memorize them, but because they show up in almost every web app.

⏱
Rate Limiting

The web_search tool in tools.py has a built-in rate limiter: max 1 request per second. It uses an asyncio Lock so only one search runs at a time, even if multiple debaters search simultaneously. This prevents overwhelming the Brave Search API and getting your key revoked.

▦
CSS Grid Collapse

The thinking sections and tool cards use a CSS Grid trick for smooth collapse animation: grid-template-rows: 1fr (open) transitions to grid-template-rows: 0fr (closed). This avoids the janky max-height animation hack that most web apps use.

📑
Per-Debater Memory

Each debater has its own message_history dictionary (self._history) in debate_engine.py. After each turn, the full PydanticAI conversation is stored so the debater remembers what it said before — without it appearing in the user prompt sent to other debaters.

Debugging Intuition

When something breaks, here is where to look. Think of this as your troubleshooting cheat sheet.

🔌
Messages not appearing

Check the SSE connection in connectSSE() (app.js) and the event_generator() in main.py. The SSE stream must be open before ensure_loop_running() is called — otherwise words get generated with no one listening.

🧠
Debater says wrong things

Check the system prompt assembly in _build_debater_instructions() (agents.py). Is the stance correct? Is the personality loaded? Is the round number right? The prompt is rebuilt from scratch every turn.

🔍
Web search not working

Check the BRAVE_API_KEY in .env and the rate limiter in tools.py. The _limiter.acquire() call might be blocking if searches pile up from multiple debaters.

📝
Formatting looks broken

Check the renderContent() method in app.js. It uses marked.js to convert Markdown to HTML, and has special handling for [[Name]] mention patterns.

⏸
Debate won't resume

Check that resume() sets state.active = True and that the frontend reconnects SSE. The loop only runs when state.active is True AND the SSE consumer is connected. Both conditions must be met.

The Config That Runs It All

Everything the app needs to run lives in a single file called .env. Here are the four settings that control the entire system.

API_BASE_URL The address of the LLM server (default: DeepSeek's API)
API_KEY Your secret key for the LLM provider
MODEL Which AI model to use (default: deepseek-reasoner)
BRAVE_API_KEY Key for Brave Search (optional — search is disabled without it)

The config.py loads these using python-dotenv's dotenv dotenv_values, which reads the .env file without touching the system environment variable space. This means your API keys stay in the .env file and don't leak into your terminal history.

The module load time matters: config.py creates a single Settings() instance when the server first starts. To pick up changes to your .env file, you need to restart the server.

📖
Good to know

This project works with any OpenAI-compatible API, not just DeepSeek. You can point it at a local model running in Ollama, a self-hosted vLLM server, or even OpenAI itself. Just change API_BASE_URL and MODEL in your .env file. This flexibility comes from using the OpenAI SDK standard — one of the most widely adopted API formats in the AI world.
